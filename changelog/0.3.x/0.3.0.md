# 0.3.0 — 2026-10-03

## Added

- **`socrata_dataframe_drop`** — drops a whole staged DataCanvas canvas, or one table on it when `table_name` is given, and reports the dropped tables with their row counts plus the tables still on the canvas. Opt-in via `SOCRATA_DATAFRAME_DROP_ENABLED=true` (default off; listed as disabled with that hint otherwise), and only meaningful with `CANVAS_PROVIDER_TYPE=duckdb`.

## Changed

- **Docker image** — production dependencies install in a `deps` stage on the build platform ([cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575), 0.13.10) and musl-only packages are pruned from it ([cyanheads/mcp-ts-core#608](https://github.com/cyanheads/mcp-ts-core/issues/608), 0.13.11); base images move to `oven/bun:1.4.2`, and the unused `MCP_FORCE_CONSOLE_LOGGING` env is gone.
- **`server.json` npm entries** launch the package bin through `npx` instead of `bun run start:*`, and the HTTP entry selects HTTP with `MCP_TRANSPORT_TYPE=http` ([cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622), 0.13.11).
- **`.env.example`** documents the 0.13.8 opt-ins `LOG_TOOL_FAILURE_PAYLOADS` ([cyanheads/mcp-ts-core#291](https://github.com/cyanheads/mcp-ts-core/issues/291)) and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` ([cyanheads/mcp-ts-core#547](https://github.com/cyanheads/mcp-ts-core/issues/547)), plus `SOCRATA_DATAFRAME_DROP_ENABLED`; the README lists `LOG_TOOL_FAILURE_PAYLOADS`.
- **Ignore files** — `.gitignore` and `.dockerignore` cover every `.env*` file (`.gitignore` keeps the templates) and `.dockerignore` the MCP Registry token files; `.mcpbignore` excludes `docs/idea.md` and `logs/`; the `package.json` `files` allowlist excludes `dist/*.mcpb`.
- **CodeQL** runs one job per language, uploading under default setup's `/language:<language>` category ([cyanheads/mcp-ts-core#470](https://github.com/cyanheads/mcp-ts-core/issues/470)).
- **Framework sync** — `framework-skills/`, the devcheck, `lint:mcp`, `lint:packaging`, `release:github`, and skill-version scripts, and `CLAUDE.md`/`AGENTS.md` re-synced with mcp-ts-core 0.13.11; `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` added for the Docker `deps` stage.
- **Recovery hints** — tool handlers no longer forward `ctx.recoveryFor(...)`; the framework fills each declared hint itself ([cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)). Internal only: callers see the same hints.

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.11 (brings `@modelcontextprotocol/server` 2.0.0 → 2.2.0). Client-visible effects:
  - Error responses carry the request id as `data.requestId`, and the text closes with `request <id>` ([cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576), 0.13.10).
  - Stack traces ([cyanheads/mcp-ts-core#519](https://github.com/cyanheads/mcp-ts-core/issues/519), 0.13.7) and request context ([cyanheads/mcp-ts-core#548](https://github.com/cyanheads/mcp-ts-core/issues/548), 0.13.8) no longer reach client error data.
  - A JSON-stringified object, or an integer sent for a string field, is repaired before validation ([cyanheads/mcp-ts-core#479](https://github.com/cyanheads/mcp-ts-core/issues/479), [cyanheads/mcp-ts-core#487](https://github.com/cyanheads/mcp-ts-core/issues/487), 0.13.9).
  - DuckDB canvas scratch files live in a private per-process directory under `CANVAS_TEMP_PATH`, which is now a parent directory ([cyanheads/mcp-ts-core#554](https://github.com/cyanheads/mcp-ts-core/issues/554), 0.13.9), and concurrent canvas spills no longer corrupt each other ([cyanheads/mcp-ts-core#561](https://github.com/cyanheads/mcp-ts-core/issues/561), 0.13.9).
  - `ctx.log` notifications to the client honor `MCP_LOG_LEVEL` ([cyanheads/mcp-ts-core#621](https://github.com/cyanheads/mcp-ts-core/issues/621)) and mask sensitive fields ([cyanheads/mcp-ts-core#630](https://github.com/cyanheads/mcp-ts-core/issues/630), 0.13.11).
