# 0.2.0 — 2026-09-22

## Changed

- **`socrata_find_datasets` `column_names`** now carries Discovery `columns_field_name` (SoQL identifiers, e.g. `cuisine_description`) instead of `columns_name` display labels (`CUISINE DESCRIPTION`), which fail to parse once they contain a space. `:@computed_region_*` entries are dropped; a result without field names yields `[]`. ⚠️ Breaking — changes the meaning of an existing output field. [#29](https://github.com/cyanheads/socrata-mcp-server/issues/29)

## Fixed

- **Non-Socrata hosts** — a 404/403 with no SODA-shaped body, a DNS `ENOTFOUND`, or an off-host redirect to another platform's JSON now map to `unknown_domain` instead of a generic error with no reason, or (for DNS) retrying to exhaustion. [#27](https://github.com/cyanheads/socrata-mcp-server/issues/27), [#37](https://github.com/cyanheads/socrata-mcp-server/issues/37), [#38](https://github.com/cyanheads/socrata-mcp-server/issues/38), [#39](https://github.com/cyanheads/socrata-mcp-server/issues/39)
- **Cross-portal dataset IDs** — `socrata_get_dataset`/`socrata_query_dataset` `not_found` now names the domain queried and, via a best-effort Discovery `?ids=` lookup, the portal actually holding the ID. [#28](https://github.com/cyanheads/socrata-mcp-server/issues/28)
- **URL-shaped `domain`** (`https://data.cdc.gov/`) is normalized to a bare hostname instead of building `https://https://…`; a value that still isn't a hostname fails fast as `invalid_domain`. [#35](https://github.com/cyanheads/socrata-mcp-server/issues/35)
- **Federated portal catalogs** — `socrata_list_portals` counts and domain-scoped `socrata_find_datasets` send `search_context` alongside `domains`, so Austin, Illinois, Mesa, and San Francisco count their federated datasets instead of near zero; San Francisco's curated entry moved to its canonical host `data.sf.gov`, and `data.iowa.gov` (dead SODA endpoint) was dropped. [#32](https://github.com/cyanheads/socrata-mcp-server/issues/32), [#36](https://github.com/cyanheads/socrata-mcp-server/issues/36)
- **`socrata_list_portals`** drops its unreachable `rate_limited` error declaration — the handler always degrades a failed count to `null` rather than throwing. [#31](https://github.com/cyanheads/socrata-mcp-server/issues/31)
- **`socrata_query_dataset` `soql_error` recovery** is chosen per upstream code (parse error, unknown column, type mismatch) instead of one static hint.
