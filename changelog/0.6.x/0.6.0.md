# 0.6.0 — 2026-10-30

## Changed

- **50-second call deadline** (#59): `socrata_query_dataset`, `socrata_get_dataset`, `socrata_find_datasets`, and the `socrata://datasets/{domain}/{datasetId}` resource now stop at a 50-second deadline shared by every request the call makes, retries and backoffs included, and fail with a retryable `Timeout` (`reason: retry_deadline_exceeded`). 0.5.1 waited as long as the portal took, so an answer arriving after 50 seconds used to succeed; retry the call, or narrow the query. A 429 whose `Retry-After` outlasts the rest of the deadline now fails at once as `rate_limited`.
- **`socrata_list_portals` and `socrata://portals` deadline** (#59): stay within the same deadline by returning null counts for the portals not yet reached; they never fail on it.
- **Staged spills are one request** (#51): staging is a single request for up to 50,000 rows, inside the deadline, where 0.5.1 paged the match across several requests that duplicated and skipped rows under a non-unique order. A staging failure or expiry keeps the inline page, with no `canvas_id` and a notice saying nothing was staged; 0.5.1 dropped the failure silently.
- **`total_count` counts the query as written** (#50): groups for a grouped query, distinct values for a distinct select. 0.5.1 reported source rows for a distinct select and omitted the count for grouped queries. The count is one bounded attempt (15 s) and is absent when it fails.
- **Past-the-end notice** (#52): an empty page past offset 0 now says whether the offset passed the end of the match, on `socrata_query_dataset`, `socrata_find_datasets`, and `socrata_list_portals`.
- **`content[]` table columns** (#49): the `socrata_query_dataset` table now shows every key any row carries; 0.5.1 used the first row's keys, so a column null in that row was missing.
- **Query and SQL echoes** (#60): the `**Query:**` and `**SQL:**` lines now read back verbatim as Markdown, as a sized code span, or a fenced block when the value holds a line break.
- **Dataframe tool descriptions**: no longer say `CANVAS_PROVIDER_TYPE=duckdb` must be set; the canvas is on by default.
- **`socrata-guide` skill 1.0 → 1.0.1**: documents the `total_count` semantics, `table_name`, and the not-staged notice.

## Added

- **`SOCRATA_CLAMP_LIMITS`** (#55, default `true`): serves a `limit` above a tool's per-call cap at the cap, with a notice. Caps: `socrata_find_datasets` 100 (ceiling 10,000), `socrata_query_dataset` 5,000 (ceiling 50,000), `socrata_dataframe_query` 10,000 (ceiling 50,000, with an SQL `ORDER BY`/`LIMIT`/`OFFSET` paging recipe). `false` restores 0.5.1's schema maxima exactly.
- **`table_name`** on `socrata_query_dataset` (#58): names the staged table, lowercased, refused if it is a SQL keyword. The notice reports a table it replaced, with the prior row count; a named call that stages nothing says why.

## Fixed

- **`socrata_find_datasets` Discovery window** (#53): 0.5.1 forwarded an `offset + limit` past Discovery's 10,000-result window, which Discovery refused with HTTP 400. `limit` is now served within the window with a notice, and `offset` of 10,000 or more fails `result_window_exceeded` before any request. `totalCountCapped` marks a count at the window as a lower bound.
- **`categories` and `tags` filters** (#54): several values are now sent as repeated parameters and ORed; 0.5.1 comma-joined them, which matched nothing.
- **`.env` under Node** (#61): a setting supplied only through `.env` is now honored under Node, as it already was under Bun, so a Node deployment whose `.env` sets a `SOCRATA_*` value picks it up.
