# 0.7.0 — 2026-11-08

## Changed

- **`socrata_dataframe_query` metadata-view names** (breaking): the canvas SQL gate refuses a column alias or CTE name spelled like a DuckDB metadata view (`pg_type`, `duckdb_tables`, `sqlite_master`) as `sql_rejected`. `SELECT primary_type AS pg_type FROM t` and `SELECT count(*) AS duckdb_tables FROM t` answered on 0.6.1; rename the alias.
- **`socrata_dataframe_query` gate refusals**: a statement naming a file path fails `sql_rejected` (`data.gateReason` `sql_read_only`) instead of `table_not_found`, and keeps the gate's own recovery hint. A `PIVOT` without `IN` is refused under a different reason, and `SHOW <table>` and `range()` now answer.
- **`socrata_dataframe_query` errors**: `invalid_sql` (a SELECT that fails to parse or prepare) and `sql_execution_error` (one that fails while running) are declared, each with a recovery.
- **`socrata_dataframe_describe` and `socrata_query_dataset`**: caller cancellation now reaches the canvas `describe()` call.
- **`sql` and `column_names` descriptions**: `socrata_dataframe_query`'s `sql` description and `sql_rejected` recovery state the metadata-view-name refusal, and `socrata_find_datasets`' `column_names` warns that a catalog-listed subcolumn can be missing from the row endpoint, which drops it from a `select` without an error.
- **Framework sync to mcp-ts-core 0.13.22**: `framework-skills/`, the `devcheck`, `lint-mcp`, `lint-packaging`, `clean-mcpb`, `release-github`, and `check-framework-antipatterns` scripts, agent docs, `.env.example` (`MCP_JWT_EXPECTED_AUDIENCE`, `MCP_JWT_EXPECTED_ISSUER`), `.mcpbignore`, and the Dockerfile skills comment.
- **`socrata-guide` skill 1.0.2 → 1.0.3**: a `not_tabular` error names the tables behind a map, chart, or story.

## Fixed

- **Alias dataset IDs** (#70): `socrata_get_dataset` and `socrata://datasets/{domain}/{datasetId}` accept a same-host views record whose `id` is another four-by-four, as `5it6-gc2r` on data.nj.gov answers with `t6tk-mr48`. `dataset_id` stays the requested ID, whose row endpoint the columns describe, and the new `canonical_dataset_id` (and ` | **Canonical ID:**` on the `content[]` ID line) carries the record's `id`. A same-host record without a four-by-four `id`, or a redirected record with a different `id`, still fails as before.
- **Table-cell line breaks** (#71): `socrata_query_dataset` and `socrata_dataframe_query` cells, and the `socrata_get_dataset` column table, render a line break as `&#10;` and `&#13;` instead of a space, so `content[]` reads back as `structuredContent`.
- **`soql_error` recovery** (#73): on a type mismatch, and on an unknown column upstream names, one bare `$limit=0` row request reads the field types from `X-SODA2-Fields` / `X-SODA2-Types` under a 15 s bound, no retries; any failure leaves today's hint and caller cancellation fails the call as cancelled. A type mismatch adds `data.referenced_columns` (`[{ field_name, type }]`) and a hint naming those fields and the casts `col::number`, `col::text`, `col::floating_timestamp`, leaving out a cast to the column's own type; a function name, or a name right after `AS`, is never read as a field. An unknown column adds `data.similar_columns`. A new hint for `query.soql.no-such-function` says casts are written `col::type` and links the function list.
- **`not_tabular` on a 403** (#74): stories, measures, files, and links answer `/resource/<id>.json` with a non-tabular 403; the failure now runs the Discovery lookup, so `data` carries `dataset_id` plus `asset_type` and `parent_dataset_ids` when listed, and the recovery names the tables (`9hpx-asd8 is a story built on e52k-ymww; query that dataset_id on data.ny.gov.`). The 403 is requested once; a failed lookup leaves the declared recovery.
- **`socrata_get_dataset` Field cell**: the field name renders exactly, as a code span, or as an escaped cell when it holds a line break or `\|`.
